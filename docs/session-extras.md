# Session extras

The smaller conveniences, each its own extension.

- **Project trust** ([`extensions/internal/project-approval.ts`](../extensions/internal/project-approval.ts)): prompts before loading project config (MCP servers, hooks, agents, rules, output styles, commands, skills) that pi would otherwise trust silently.
- **Plan mode** ([`extensions/plan-mode/`](../extensions/plan-mode)): `plan_mode_complete` tool, tool snapshot/restore that survives `/reload`. `/plan [description]` enters plan mode and sends the description as the first prompt; it never leaves plan mode. `pi --plan` starts a session in plan mode, as Claude's `--permission-mode plan` does. Leave by choosing "Execute the plan" after `plan_mode_complete`, or with `Ctrl+Alt+P`, which toggles plan mode; Claude's `Shift+Tab` mode cycle has no equivalent, since pi binds `Shift+Tab` to cycling the thinking level.
- **Todo list** ([`extensions/todo.ts`](../extensions/todo.ts)): persistent overlay, status machine, compaction-safe.
- **AskUserQuestion** ([`extensions/question.ts`](../extensions/question.ts)): 1-4 questions per call (asked in sequence), each with `header` and 2-4 options, single- or `multiSelect`, plus free-text. Honors `askUserQuestionTimeout` (`60s`/`5m`/`10m`, scope "User or managed" — a project's own settings.json cannot set it), read from managed settings then `~/.claude/settings.json`. On the TUI overlay only: a visible countdown for the last 20 seconds, any keypress restarting the timer, and on firing, a multiSelect submits whatever was already checked, a single-select submits nothing, and the tool result tells the model to proceed on its own judgment rather than reading as a cancel. **Not implemented:** restarting the timer on terminal focus-in, since pi's TUI input stream is not confirmed to carry that escape sequence; and the timeout on the RPC dialog-primitive fallback (no terminal, so no keypress or countdown to drive it); there a `multiSelect` question takes one option, since the dialog's select returns a single choice.
  Remote responders (a chat bridge, for example): on the TUI each question is first emitted on `pi.events` as `pi-code:question:v1`, typed as `RemoteQuestionOffer` in the same file. A listener that calls `claim()` synchronously during emission receives the only settle handle. The overlay opens either way and the first answer, local or remote, wins. Answers are 1-based option indices, free text only when `allowFreeText`, or `cancel`; `pass` or an invalid reply withdraws the remote side and leaves the overlay open. `touch()` restarts the overlay idle timer, and the offer's `signal` aborts once the question is settled, after which replies are rejected.
- **Think keyword** ([`extensions/thinking.ts`](../extensions/thinking.ts)): `ultrathink` raises reasoning to the max for one turn, matched on a word boundary, only ever raising, restored once the turn settles. It is the only keyword, as in Claude: `think`, `think hard`, `think more` and similar phrases pass through as ordinary prompt text. **Divergence:** Claude adds an in-context instruction and leaves the API effort level unchanged; pi has no separate in-context channel for this and its thinking level is how deeper reasoning is requested, so the keyword moves the level and restores it after.
- **`/context`** ([`extensions/context-usage.ts`](../extensions/context-usage.ts)): reports used/window/free/percent of the model's context window, reading pi's live usage so it reflects a compaction.
- **`/init`** ([`extensions/init.ts`](../extensions/init.ts)): generates a project context file; detects an existing `AGENTS.md`/`CLAUDE.md` (proposes improvements) or creates `AGENTS.md`, ingesting `.cursor/rules`, `.cursorrules`, and `.github/copilot-instructions.md` when present; drives the main agent with full tools so it analyzes the codebase and writes the file itself.
